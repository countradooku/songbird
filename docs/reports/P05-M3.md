## The gate's M3 items

| Gate item | Evidence |
| --- | --- |
| **Invite links with expiry, use limit, revocation** | Live: a one-use link is spent after Carol's join (404 for Dave); a one-second link stops working and the sweep forgets it; a revoked link is 404. Only the policy's `links` role manages links (403 for a member). |
| **The server cannot use a link from its own database** | It stores `SHA-256(auth)`. `auth` and the key to the group's info are derived by the app from a secret that travels only in the link's fragment. |
| **Wrong links tell nothing** | Unknown handle, wrong secret, used up, expired, revoked: one 404; constant-time comparison; joins with a wrong secret are refused before any work |
| **"Admin approval for new members"** | Live: opening an approval link gives only the encrypted info (no members); joining is 403 `approval`; asking is idempotent; members with the `add` role list requests oldest first; approving is adding (the commit answers the request); declining |
| **Parallel joins never exceed a link's uses** | The use is counted in the transaction that stores the commit (compare-and-set on the epoch). Live race: five people join at once, round after round, with a two-use link: one join per epoch, exactly two joined, the rest 404. A retried join that already won is recognised (live) |
| **Guessing** | Handles are 128 random bits and `auth` 256; opening, joining and asking have their own budget per account, shared by its devices (keyed records in `valkey-hot`; live: 429). Accounts already cost an invite or proof of work, so no IP-range record is added for these authenticated endpoints |

  expiry); pending join requests (**the account that asks**).
