# P05-M1 — The MLS delivery service: progress

- Date: 2026-11-16
- Status: **in progress.** The core is built and tested (D-0066). The registry, `api` and
  send-path integration are next. The gate is not reached; nothing is committed yet.
- Plan: [P05-plan.md](P05-plan.md) (D-0065). Decisions: D-0066.
- Machine: Windows 11 Pro, `rustc 1.99.1`. aws-lc-sys builds with `AWS_LC_SYS_PREBUILT_NASM=1`
  (its own prebuilt objects; no system change). CI and production build on Linux as before.

## Built

| Piece | Where | What it does |
| --- | --- | --- |
| Verify-only provider | `crates/groups/src/crypto.rs` | OpenMLS's crypto trait on aws-lc-rs: hashes, Ed25519 verification, HMAC, HKDF. It refuses every operation that needs a secret. Groups use X-Wing `0x004F`. |
| State store | `crates/groups/src/state.rs` | One group's `PublicGroup` state as postcard bytes, tagged with OpenMLS's storage version; at most 64 queued proposals. |
| Wire parsers | `crates/groups/src/wire.rs` | The allocation-free `PrivateMessage` prefix parser (send path), the commit bundle, and the `GroupInfo` signer; minimal varints only. |
| Delivery-service core | `crates/groups/src/ds.rs` | `Group::create`, `load`, `record` and `apply_commit`, with every check in D-0066; the roster sorted by device. |
| Client harness | `tests/groups` | Simulated devices on OpenMLS's RustCrypto provider: create, add, remove, update, rejoin, messages. |
| Fuzz targets | `fuzz/fuzz_targets/mls_wire.rs`, `mls_commit.rs` | The parsers, and arbitrary bundles against a real post-quantum group. |

## Evidence so far

- `cargo test --release -p songbird-groups -p songbird-groups-harness`: 22 tests, all pass.
  - `lifecycle` (11): a group's life with reloads; and the refusals:
    - a commit sent by another device;
    - an unknown device added, or a known device added twice;
    - a missing, swapped or extra Welcome;
    - a stale or foreign `GroupInfo`;
    - a stale epoch;
    - the size and bundle limits;
    - a forked group;
    - an application message as a commit;
    - a stranger's external commit, and a twin leaf for one device;
    - creation checks.
  - `convergence` (2): six concurrent commits on one epoch, exactly one winner per round and no
    fork; and a property test (24 random sequences of adds, removals and races) in which every
    honest client always has the server's epoch and roster and reads everyone.
  - Unit tests: RFC 5869 and RFC 8032 known answers, the parsers' malformation and minimality
    tests, and the manifest guard.
- `cargo clippy -D warnings` is clean on both crates; the fuzz targets type-check.
- Measured:
  - X-Wing commit size: 5,479 to 32,611 bytes while adding 20 members one at a time.
  - Stored tree: 1.67 KB per member in postcard, against 6.26 KB in JSON.

## Left for M1

1. **Registry:**
   - `group:[id]` in SurrealDB: the record (postcard), the epoch, a roster table for the send
     path, and the hashes of the last commits (so a retried commit is answered as accepted);
   - compare-and-set on the epoch together with an outbox row;
   - the live race test: N `api` requests on one epoch, one winner.
2. **`api` endpoints** (PROTOCOL §6):
   - create a group;
   - submit a commit bundle;
   - fetch the ratchet tree and `GroupInfo`, for members, and for devices named in a pending
     Welcome or rejoining;
   - fan-out through the send library: the commit to the old and new rosters, the Welcome to
     the added devices; acknowledged only after the mailboxes stored it, with the outbox
     re-driven by the worker after a crash.
3. **Send path:**
   - a group application flag on `Send`: the group, then one `PrivateMessage`;
   - the prefix checked (application type, this or the previous epoch), the sender in the
     roster, fan-out from the roster;
   - flag `0x01` refused; D-0064's interim group lane retired for these groups.
4. **KeyPackages:** the D-0051 parser extended to `0x004F` (X-Wing init and encryption keys,
   1,216 bytes each; the 2,048-byte limit raised).
5. **Supply chain:** cargo-vet entries and cargo-deny for the 11 new crates.
6. **Proof:**
   - run both fuzz targets (needs nightly);
   - a fixture test that stored records reload across OpenMLS versions.
7. **Docs:**
   - PROTOCOL §6;
   - threat-model §1 rows (the roster; the group record; the stored `GroupInfo` and tree),
     awaiting the owner;
   - this report completed with the gate.
