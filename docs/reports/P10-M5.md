## What was built

| Piece | Where |
| --- | --- |

| Backups to the Songbird vault (signed by this device), an encrypted folder, S3 and Nextcloud (`WebDAV`) | `backend/backup.rs` (`store_for`, `back_up`, `delete`); store intents `back_up_now`, `disable_backups` |
| Google Drive, OneDrive, Dropbox and iCloud Drive say "Coming soon" with why (D-0119 §6) | `features/backups/mod.rs` (`dest_note`, `dest_ready`) |

| Property | Evidence |
| --- | --- |

## Finishing checklist

- Radius, typography, spacing, alignment, colour and surfaces: passed. Every new element is an
  existing `ui` part (`field`, `labelled_field`, `btn`, `numeric_code`, `qr_code_live`,
  `busy_bar`, `status_line`); no literal colours or sizes.
- Fixed: on the restore screen a typo turned the helper red and added a second error line;
  the helper line now carries the error alone.
- Hover and pressed: from the `ui` controls; nothing new.
- Motion: the inventory's new lines verified in the running app (page changes as the other
  transfer pages; the QR replaces the bar in place; the typo is colour and text only).
- Accessibility: the QR has an image label; the six digits are text; every action is a button
  reachable by keyboard; "Or paste the code" is a labelled field.
- Platforms: checked at 1180 × 780 and 390 × 844 on macOS. Not checked on iOS, Android,
  Windows or Linux in this milestone.
- Left as is: "Coming soon" rows still show an empty radio (the `ui` layer's `Row` has no
  disabled state; choosing one only keeps Continue disabled). A disabled row is a `ui`
  addition for later.

## Not done here, and why

- Real Google Drive, OneDrive and Dropbox sign-in (the owner registers the OAuth apps,
  D-0119 §6). NSH 0.6 has an auth-session API (`nsh_core::auth_session`) the mobile sign-in can
  use then.
- iCloud Drive's native half (with the iOS host projects).
- The vault and account recovery from the running app against a live server were not run in
  this milestone (no `api` was running); they are covered by `gate_p10` and `devices_live`, and
  the app builds the same requests.
- Chats and messages are the mock's until app-core (A2): a restored message comes back as
  text, and chats this device didn't have take the first chat's look.
