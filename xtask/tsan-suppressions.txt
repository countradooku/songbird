# tokio 1.54.1 I/O driver, reading a socket's readiness after epoll reports it.
#   Write: `TcpStream::new` -> `Handle::add_source` -> `RegistrationSet::allocate` creates the
#          `Arc<ScheduledIo>` on the registering thread and hands its address to epoll as the token.
#   Read:  the driver thread gets the token back from `epoll_wait`, then `dispatch_event` calls
#          `set_readiness` and `wake` on it, which take the readiness word and the waiters mutex.
#   TSan sees no ordering edge for any field of that fresh block, so it flags each field the
#   driver touches in turn (with only the first rule, run 43617500246 reported `wake` locking the
#   waiters mutex on the same block). The hand-off goes through the kernel. No Songbird frame is at
#   either access, Songbird crates forbid `unsafe`, and Songbird implements no wakers (only
#   `Waker::noop`), so nothing of Songbird's runs under these frames. Seen in
#   `songbird-e2e --test invariants` and `songbird-link --test link` (nightly runs 43195207467,
#   43586736672, 43617500246, Linux x86_64). It does not occur on macOS (kqueue). Tracked in
#   docs/THREAT_MODEL.md section 6: re-check on every tokio upgrade.
