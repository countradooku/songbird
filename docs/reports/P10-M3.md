## Findings

1. **`WebDAV` cannot give an atomic compare-and-swap.** The conformance suite's race (eight
   writers on one generation) found that Apache `mod_dav` evaluates `If-Match` and then writes:
   all eight won. An exclusive `LOCK` around the swap reduced it, but `mod_dav`'s own lock is not
   atomic either: two of eight concurrent `LOCK`s on one resource returned 200 (reproduced with
   `curl`). So `WebDAV` and Google Drive (no conditional write at all, as the plan said) declare
   `atomic_swap() == false`: the run reads the manifest back after swapping, and a device
   overtaken after that is refused as a fork at its next run. Only the primary writes, so a race
   needs two primaries, which only an account recovery can briefly create. Stated in the threat
   model (§6).
2. **RustFS 1.0.5 honours S3 conditional writes** (`If-None-Match: *`, `If-Match`): S3 keeps the
   strict guarantee, checked by the race; MinIO was not needed.
3. Alpine's `httpd` image has no DBM driver for `mod_dav`'s lock database; the Debian image has.

## Changes from the plan

- `BackupStore::atomic_swap` and the read-back after a swap (finding 1).
- `run::backup` takes its options by value (a backup can run on a spawned task).
- The emulators are in-process hyper servers in the test file, not containers.
