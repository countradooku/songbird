## Properties and their evidence

| Property | Evidence |
| --- | --- |
| Large files stream with one chunk of memory | `Encryptor::push` and `finish` hold at most 64 KiB plus a tag; `pushing_in_odd_slices_gives_the_same_bytes` |
| Resume and range reads verify chunk by chunk, in any order | `chunks_open_in_any_order_for_range_requests` |
| Reordering, truncation, extension and bit flips are caught at their chunk | `reordering_truncating_extending_and_flipping_are_caught_at_their_chunk`; proptest `any_file_round_trips_and_any_flipped_byte_is_refused` |
| Key-committing; no suite downgrade | `the_wrong_key_salt_digest_or_version_is_refused_before_any_chunk` |
| Padded into buckets, padding authenticated as zeros | `padding_must_be_zeros_and_the_real_length_is_the_pointers`; `crates/proto` media tests (Padmé bound ≤ 12 %, idempotent, monotone) |
| The server can tell a legal ciphertext length from any other | `every_length_up_to_a_few_megabytes_round_trips_and_nothing_else_is_legal` (exhaustive to 4 MiB), `ciphertext_lengths_invert` (proptest to 1 TiB) |
| Forwarding shares nothing | `fresh_keys_and_salts_differ` (the rule itself is PROTOCOL §7.1; the server side, single-use grants and random IDs, is M2) |
| Two independent implementations agree | `published_vectors` and `node tools/attachment-vectors/check.mjs` → "6 vectors match the independent implementation" |

## Numbers

AES-256-GCM against ChaCha20-Poly1305: encrypt / decrypt throughput in MB/s, median of 9 runs.
Release build on a Ryzen 9 7950X with Windows 11 Pro 10.0.26300 and aws-lc-sys 0.47 (prebuilt
NASM objects).

| Size | ChaCha20-Poly1305 | AES-256-GCM |
| --- | --- | --- |
| 64 KiB | 852 / 1,160 | 958 / 1,346 |
| 1 MiB | 2,383 / 2,400 | 3,087 / 3,185 |
| 64 MiB | 2,246 / 2,501 | 2,950 / 3,413 |

AES-256-GCM is the default (version 2), and readers accept both. A 2 GiB video encrypts in
under a second on this machine. On phones, the network is the bottleneck, not the cipher.

## Changes from the plan

- **The client library does not encrypt.** `crates/client` cannot link `songbird-content`: the
  `no_service_links_content` test covers every crate, so that the server can never decode
  content. The format stays in `songbird-content` as the prompt asks. `crates/client` gets the
  transport (resumable upload, ranged download) in M2 and M3, and the live tests encrypt with
  `songbird-content` from a test crate.

## Open risks

- The ARM throughput is not measured until the apps exist.
- The fuzz target is built but not yet run. It runs in the gate's fuzz batch, with the owner's
