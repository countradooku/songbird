## Properties and their evidence

| Property | Evidence |
| --- | --- |
| Devices converge on the newest edit of each key, whatever they do offline and whatever order they sync in, with skewed clocks | proptest `devices_converge_on_the_newest_edit_of_each_key` (512 cases, 2–4 devices, ±1 h skew, up to 80 operations) |
| A bad clock never pins a key | proptest `a_device_with_a_clock_days_ahead_never_pins_a_key` (2 to 400 days ahead) |
| Deletes and offline edits converge; tombstones expire and stale edits do not come back | `a_delete_and_an_offline_edit_converge_by_their_stamps`, `tombstones_are_collected_after_the_horizon…` |
| A withheld, swapped or rolled-back record is caught | `a_withheld_record_is_caught`, `a_record_swapped_or_changed_is_caught`, `a_rollback_to_an_older_version_is_caught` |
| A key rotation rewrites everything under fresh IDs; the old key cannot read it | `a_key_rotation_rewrites_everything…` (memory); live rotation |
| Sizes say little | `records_are_padded_so_sizes_say_little`; the server refuses unpadded lengths (`record_lengths_are_padme_values_with_a_tag`, live 400) |
| Concurrent writers lose nothing on the real store | `two_devices_converge_through_the_real_store_and_concurrent_writers_never_lose_an_edit` (eight writers) |
| Versions, caps, other accounts and pending devices | `the_server_checks_versions_lengths_caps_accounts_and_pending_devices` |
| Objects are the account's own; deletion leaves no row or object | `objects_are_the_accounts_own_and_deletion_leaves_nothing`; worker deletion verifies objects gone |
| Decoders are bounded | `a_huge_declared_count_allocates_nothing`, proptest `decoders_never_panic`, fuzz `storage` |

## Numbers

Apple M5 Pro, 48 GB, macOS 27.2.1; the compose stack (SurrealDB 4.0.1, Valkey, RustFS); one
`api` in the test process (`store_latency`):

| Operation | p50 | p99 |
| --- | --- | --- |
| One changed record: head, write | 24 ms | 113 ms |
| Nothing changed: head only | 5.6 ms | 36 ms |
| A fresh device reads 501 records | 30 ms | 36 ms |
| First write of 500 records | 93 ms (one run) | — |

Development numbers; the production host class is measured with Prompt 13.

## Changes from the plan

- The smallest padded record is 256 bytes, not 64: at 64 two ordinary settings had different
  sizes.
- The manifest holds a digest of the IDs, not the IDs: 76 bytes per write whatever the store's
  size; the ID list is read only when the version moved.
- Rotating the key on device removal is a library call (`songbird_sync::rotate`); the app makes
  it when it removes a device (M5).
