## Numbers: the incremental cost on a large simulated history

About a million messages (2,000 chats × 501), 22,000 media messages (about 18,000 distinct files of
20, 60 or 200 kB; every fifth a forward), 500 contacts: 1,649 MB of plaintext. Apple M5 Pro,
48 GB, macOS 27.2.1, release build. "A day" is one new message in each of the 2,000 chats;
"deleted" removes the 25 oldest messages of every chat (50,000 messages).

| Step | In memory: new chunks / MB | On the vault: new chunks / MB |
| --- | --- | --- |
| First backup | 665 / 1,670.9 | 651 / 1,670.2 |
| Nothing changed | 0 / 0 | 0 / 0 |
| A day of messages in every chat | 2 / 3.7 | 1 / 1.5 |
| The oldest messages of every chat deleted | 4 / 9.6 | 7 / 19.5 |

Each run took 46 to 54 s of wall time, which is almost all the **test's** synthetic generator:
fed pre-generated, the writer took 0.6 s for the million records; media are sealed at the
measured 518 MB/s (M1); the vault stored 1.67 GB in the same minute (chunks are uploaded while
the writer works, eight at a time). The vault after four backups: generation 4, 1,662.7 MB in 646
chunks (the replaced ones deleted).

**The first measurement found a cost problem**: with messages ordered chat by chat, one new
message in each of 2,000 chats touched every chunk of the messages stream (64 chunks, 158 MB a
day). Ordering every message by time across chats (§11.5) puts a day's messages at the end of
the stream: 1 or 2 chunks. Clearing old messages likewise touches the start. A whole new
1.6 MB-per-chat pattern (a chat's own history edited deep in the past) still re-uploads the
chunks around each edit, which is what content-defined chunking promises.

## Changes from the plan

- Recovery reuses the link request (§4.6) instead of a new message: the same two key proofs and
  the same PIN and passkey checks, with the account identity key's signature in front. Tokens
  carry their kind, so a link token, a recovery token and a hand-over token cannot stand in for
  one another.
- Records are ordered by time across chats (the cost finding above); the writer no longer
  allocates 1 MiB per small media file.
- `transfer::connect_via` dials one address (tests use a relay).
