## Changes from the plan

- **The first parental policy is handed over as a QR code, not through the server.** I first built
  it relayed sealed through a provisioning channel. The parent's signed write, then the child's
  install, would have let the server tie the two accounts together by timing, against D-0105.
  The policy is about 200 bytes, so the parent's device shows it as a third code.
- **A linked device starts from an empty replica.** Re-keying its own replica would let its
  first-run defaults overwrite the account's settings.
- **The child's side was missing.** A single device stood in for both sides; it is still the
  preview when the server is off.

## Not verified

- The live flows have not been run between two real phones: device linking (new device and main
  phone) and parental linking (parent and child). They need two registered devices on the server
  and cameras. The camera's own device checks are listed in `CAM-gate.md`.
- Presence and nudges send nothing until app-core (A2) can seal for contacts' devices.
