## Properties and their evidence

| Property | Evidence |
| --- | --- |
| Every member derives the same key for a sender; senders' and calls' keys differ | `members_agree_and_a_removal_rotates_the_keys`; proptest `sender_keys_differ_by_identity_secret_and_call` |
| A membership change rotates the keys to the next index, and a removed device cannot derive them | `members_agree_and_a_removal_rotates_the_keys` (Carol, removed, still holds epoch 1's key; Alice and Bob agree on epoch 2's) |
| No two of 16 consecutive epochs share a key index | proptest `consecutive_epochs_never_share_a_key_index` |
| Cards open only under the link key; the ID the server sees opens nothing; tampering is caught | `cards_are_sealed_under_the_link_key_only`; proptests `a_tampered_card_never_opens`, `opening_arbitrary_bytes_never_panics` |
| Signalling is bounded (exactly one of secret or group, media set, key index < 16, 32-byte keys, identity 1–64 bytes) | `signalling_is_bounded`, `identities_are_bounded` |
| Apps never ring past 2 minutes | `ringing_is_capped` |
| No key in `Debug` | `debug_prints_no_key` |
| Two independent implementations agree | `the_published_vectors_hold` and `node tools/call-vectors/check.mjs` → "call vectors: 10 lines rebuilt independently, all match"; `tools/content-vectors` (protox) → "all 38 vectors match content.proto", the 5 call vectors among them |

## Changes from the plan

- **Domain-separation strings** follow the existing `songbird.v1/<name>\0` convention
  (`songbird.v1/call-1to1\0`, `…/call-sender\0`, the MLS label `songbird.v1/call`) rather than the
  plan's "songbird call … v1" sketches.
- **Sending switches to a new index 1 second after a commit**, so receivers have installed it;
  until then a removed device may still decrypt, which is why M2 also removes it from the SFU.
- **`tools/content-vectors` was broken by Prompt 6**: it read every directory under `vectors/`,
  and `attachment/` has no `vectors.json`. It now checks only protobuf vector sets.
- The content compatibility test used tag 15 for "a newer writer's body"; it now uses 16, since 15
  is `call`.

## Open risks

- LiveKit derives its frame key from the sender key itself (PBKDF2 by default); the harness (M4)
  is what proves the whole chain decrypts across devices.
- The fuzz target is built with the gate's batch and runs with the owner's go-ahead.
