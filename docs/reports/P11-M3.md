## Not yet

- **The real sandboxes.** Every verifier is tested against emulators written from the
  providers' documentation. The App Store sandbox, Play licence testers and Mollie's test mode
  need the owner's accounts and keys (`docs/RUNBOOKS/billing.md`, "Owner's set-up"); the gate
  report lists them.
- **The Apple root's fingerprint** pinned in `main.rs` must be checked against apple.com before
  release (billing refuses to start in production otherwise, which fails safe).
- **Deployed configuration.** Like every service, the deployed `billing.toml` is the idle
  skeleton until the services are configured on the hosts; its secrets go to a directory
  readable by `billing_uid` only, as push's do.

## Changes from the plan

- Apple's chains are verified with **rustls-webpki** (already in the tree) and a 60-line strict
  DER walk for the marker extensions, rather than an X.509 parser on network input.
- Google's voided purchases revoke **for good** (a later API read cannot undo it); Apple's newer
  state may clear an older revocation (a later period paid).
- A Mollie period stays paid **7 days** past its next charge date (SEPA Direct Debit is slow).
- Lapsed subscription rows go after **400 days** (past refund and chargeback windows).
