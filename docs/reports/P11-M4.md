## Changes from the plan

- **Passes per vault, per day.** A pass is presented once a day per vault and covers that day
  and the next (a backup across midnight); the vault keeps the latest pass's level as its quota.
- **Creation tokens are counted per keyed account tag** in the registry (durable for the
  180-day window); day passes per account in `valkey-hot`. So the server knows which accounts
  ask for vault tokens, never which vault: stated in the threat model.
- **Whoever holds the recovery key can now write** to its vault, not only the account's primary.
  The key already recovers the whole account (D-0119 §2), so this adds nothing an attacker with
  the key lacked; without the key nobody can write.
- The mailbox is in `api` (any node), behind `[api.tokens]`.
