## Properties and their evidence (the gate's items)

| Property | Evidence |
| --- | --- |
| **Presence reaches only allowed contacts** | `presence_reaches_only_contacts_and_invisible_sends_nothing`: Bob (a contact) gets it on both devices; a batch reaching Carol without her key is refused whole (401) and nobody gets anything; with her key she gets it |
| **Invisible mode sends nothing** | same test (the server's accepted count does not move; Bob receives nothing); proptest `invisible_never_sends_anything` |
| The sender learns nothing about who is online | same test: the same 204 with no body when a recipient's device is offline |
| **Nudge rate limits** | `nudges_are_held_to_their_budgets_and_blocks_drop_them`: six nudges to Bob, three pass (pair burst); another sender has its own; Alice's sender budget of five leaves two for Erin; Bob's block drops Frank's; the counts match the metrics |
| Debounce, last state always sent, replies once | proptest `sends_are_debounced_and_the_last_state_is_always_sent`; `going_online_then_away_sends_both_debounced`; `replies_go_once_per_contact_and_only_when_visible` |
| Bounded decoders | `batches_round_trip_and_decode_strictly`, proptest `the_decoder_never_panics` |

## Numbers

A 1,024-device sealed batch (64 contacts with 16 devices each, 200-byte payloads, 205 KiB, 16
devices online): p50 3.2 ms, max 10 ms over 19 runs (Apple M5 Pro, compose stack, in-process
router). The per-range budget refused the 20th batch, as configured.

## Changes from the plan

- The sealed endpoint is HTTP only; a WebSocket twin is not needed at these numbers.
- Presence budgets are per IP range, counted per device addressed, not per recipient account.
